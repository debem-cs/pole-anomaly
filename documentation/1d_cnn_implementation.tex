\section{Neural Networks: Theory and Fundamentals}
This section provides a self-contained introduction to neural networks, building the theoretical foundation necessary to understand the 1D-CNN classifier implemented in this project. No prior knowledge of machine learning is assumed.

\subsection{The Artificial Neuron}
A neural network is built from simple computational units called \textbf{neurons} (or \textbf{perceptrons}). Each neuron takes a vector of inputs $\mathbf{x} = [x_1, x_2, \ldots, x_n]$, multiplies each input by a learned \textbf{weight} $w_i$, adds a \textbf{bias} term $b$, and passes the result through a non-linear \textbf{activation function} $\sigma$:
\begin{equation}
    y = \sigma\!\left(\sum_{i=1}^{n} w_i x_i + b\right) = \sigma(\mathbf{w}^T \mathbf{x} + b)
\end{equation}

The weights and bias are the \textbf{learnable parameters} of the neuron. During training, these values are adjusted so that the neuron's output $y$ matches the desired output for a given input.

\subsubsection{Activation Functions}
Without the non-linear activation function $\sigma$, stacking multiple neurons would be equivalent to a single linear transformation---no matter how many layers are used, the overall mapping would remain linear. Common activation functions include:
\begin{itemize}
    \item \textbf{ReLU} (Rectified Linear Unit): $\sigma(z) = \max(0, z)$. The most widely used activation in modern networks. It outputs zero for negative inputs and passes positive values unchanged. This introduces non-linearity while avoiding the vanishing gradient problem that plagued earlier functions like Sigmoid.
    \item \textbf{Sigmoid}: $\sigma(z) = \frac{1}{1 + e^{-z}}$. Squashes the output to the range $(0, 1)$, useful for binary probability outputs.
    \item \textbf{Softmax}: Applied to a vector of logits $\mathbf{z}$, it converts them into a probability distribution: $\text{softmax}(z_i) = \frac{e^{z_i}}{\sum_j e^{z_j}}$. Used in the output layer for multi-class classification to ensure the predicted probabilities sum to 1.
\end{itemize}

\subsection{From Neurons to Networks}
A \textbf{neural network} is formed by organizing neurons into \textbf{layers}:
\begin{itemize}
    \item \textbf{Input layer}: Receives the raw data (e.g., a 512-point signal window).
    \item \textbf{Hidden layers}: Intermediate layers that progressively transform the data. Each layer extracts increasingly abstract features from its input. For example, the first hidden layer might detect simple edges, while deeper layers combine those edges into complex shapes.
    \item \textbf{Output layer}: Produces the final prediction (e.g., 7 class probabilities for our anomaly classifier).
\end{itemize}

When every neuron in one layer is connected to every neuron in the next, the layer is called a \textbf{fully connected} (or \textbf{dense}) layer. The full computation from input to output is called the \textbf{forward pass}.

\subsection{The Loss Function}
To train the network, we need a mathematical measure of how wrong its predictions are. This is the \textbf{loss function} $\mathcal{L}$, which compares the network's output $\hat{y}$ to the true label $y$. The goal of training is to minimize this loss.

For multi-class classification, the standard loss function is \textbf{Cross-Entropy Loss}:
\begin{equation}
    \mathcal{L} = -\sum_{c=1}^{C} y_c \log(\hat{y}_c)
\end{equation}
where $C$ is the number of classes, $y_c$ is 1 for the true class and 0 otherwise (one-hot encoding), and $\hat{y}_c$ is the predicted probability for class $c$. This loss is zero when the prediction is perfect and increases sharply when the model assigns low probability to the correct class.

\subsection{Gradient Descent and Backpropagation}
Training a neural network means finding the values of all weights $\mathbf{w}$ and biases $b$ that minimize the loss $\mathcal{L}$.

\subsubsection{Gradient Descent}
Imagine the loss function as a high-dimensional landscape where the height at each point represents the error for a particular configuration of weights. Gradient descent works by:
\begin{enumerate}
    \item Computing the \textbf{gradient} $\nabla_\mathbf{w} \mathcal{L}$---the vector of partial derivatives of the loss with respect to each weight. This points in the direction of steepest increase.
    \item Taking a step in the \textbf{opposite} direction (downhill) to reduce the loss:
    \begin{equation}
        \mathbf{w} \leftarrow \mathbf{w} - \eta \cdot \nabla_\mathbf{w} \mathcal{L}
    \end{equation}
    where $\eta$ is the \textbf{learning rate}, a hyperparameter controlling the step size. Too large and the optimizer overshoots the minimum; too small and convergence is impractically slow.
\end{enumerate}

\subsubsection{Backpropagation}
Computing the gradient of the loss with respect to every weight in a deep network is made efficient by the \textbf{backpropagation algorithm}. It applies the chain rule of calculus layer by layer, propagating the error signal backward from the output layer to the input layer:

For a weight $w$ in layer $l$ that produces output $z_l = w \cdot a_{l-1} + b$ (where $a_{l-1}$ is the activation from the previous layer), the gradient is decomposed as:
\begin{equation}
    \frac{\partial \mathcal{L}}{\partial w} = \frac{\partial \mathcal{L}}{\partial z_l} \cdot \frac{\partial z_l}{\partial w} = \delta_l \cdot a_{l-1}
\end{equation}
where $\delta_l = \frac{\partial \mathcal{L}}{\partial z_l}$ is the \textbf{error signal} at layer $l$. The key insight is that $\delta_l$ can be computed recursively from $\delta_{l+1}$, making the computation scale linearly with network depth rather than exponentially.

\subsubsection{Stochastic Gradient Descent and Adam}
In practice, computing the gradient over the entire dataset is prohibitively expensive. \textbf{Stochastic Gradient Descent (SGD)} approximates the true gradient using a small random subset (\textbf{mini-batch}) of the data. The \textbf{Adam} optimizer (used in this project) extends SGD by maintaining adaptive per-parameter learning rates using exponential moving averages of the first and second moments of the gradients, leading to faster and more stable convergence.

\subsection{Regularization: Preventing Overfitting}
A model that memorizes the training data but fails to generalize to unseen data is said to \textbf{overfit}. Several techniques prevent this:

\begin{itemize}
    \item \textbf{Dropout}: During training, a random fraction of neuron activations are set to zero at each forward pass (e.g., 40\% dropout). This forces the network to learn redundant representations rather than relying on any single neuron, acting as an implicit ensemble of smaller networks.
    \item \textbf{Batch Normalization}: Normalizes the input to each layer by subtracting the batch mean and dividing by the batch standard deviation. This stabilizes the distribution of activations throughout training, enabling higher learning rates and faster convergence.
    \item \textbf{Early Stopping}: Monitor the validation loss during training. When it stops improving for a set number of epochs (\textbf{patience}), training is halted and the best-performing weights are restored. This prevents the model from continuing to memorize noise in the training set.
\end{itemize}

\subsection{Convolutional Neural Networks (CNN)}
Standard fully connected networks treat each input element independently, ignoring spatial or temporal relationships. \textbf{Convolutional Neural Networks} address this by using \textbf{convolutional layers}, which slide a small learnable filter (or \textbf{kernel}) across the input to detect local patterns.

\subsubsection{The Convolution Operation}
For a 1D input signal $x[t]$ and a kernel $k$ of size $K$, the convolution produces a feature map:
\begin{equation}
    (x * k)[t] = \sum_{i=0}^{K-1} k[i] \cdot x[t + i]
\end{equation}

This operation has three key properties:
\begin{enumerate}
    \item \textbf{Local connectivity}: Each output element depends only on a small neighborhood of the input (the receptive field), not the entire signal.
    \item \textbf{Weight sharing}: The same kernel is applied at every position along the signal, drastically reducing the number of parameters compared to a fully connected layer.
    \item \textbf{Translation equivariance}: If a pattern shifts in time, the corresponding activation in the feature map shifts by the same amount. The network detects the pattern regardless of where it appears.
\end{enumerate}

\subsubsection{Pooling}
After convolution, \textbf{pooling layers} downsample the feature maps by taking the maximum (\textbf{MaxPooling}) or average (\textbf{AvgPooling}) over non-overlapping regions:
\begin{equation}
    \text{MaxPool}(x)[t] = \max_{i \in [2t, 2t+1]} x[i]
\end{equation}
Pooling reduces the spatial resolution, lowers computational cost, and increases the effective receptive field of subsequent layers. For a window of 512 points, three MaxPool layers with kernel 2 reduce the sequence from 512 $\rightarrow$ 256 $\rightarrow$ 128 $\rightarrow$ 64 points.

\subsubsection{Why 1D-CNN for Anomaly Detection?}
In this project, the input is a \textbf{1D time series} (gamma dose rate vs. time), not a 2D image. A 1D-CNN is the natural choice because:
\begin{itemize}
    \item Anomaly shapes (Bell, Square, M, etc.) are defined by their \textbf{local temporal morphology}---the specific sequence of rises, plateaus, and falls. 1D convolutions are designed to detect exactly these local patterns.
    \item The \textbf{translation equivariance} of convolutions means the network can detect an anomaly regardless of where it appears in the signal window.
    \item Compared to recurrent networks (RNNs/LSTMs), CNNs are \textbf{highly parallelizable}, making them significantly faster for both training and inference on GPU hardware.
    \item The small kernel sizes (5--7 points) match the temporal scale of the anomaly features, and stacking multiple convolutional blocks builds up the receptive field to capture the full anomaly structure (80--400 points).
\end{itemize}

\section{1D-CNN Implementation}
This section describes the concrete PyTorch implementation of the 1D-CNN for multi-class anomaly classification. The codebase is organized into modular scripts within the \texttt{1D-CNN/} directory, with full CUDA GPU acceleration support.

\subsection{Data Processing (\texttt{train.py})}
The data loading and preprocessing logic is embedded in the \texttt{load\_data()} function within \texttt{train.py}. It bridges the synthetic \texttt{.csv} generator and the neural network through the following steps:
\begin{enumerate}
    \item \textbf{Temporal Split:} The continuous signal is split chronologically \textit{before} windowing: the first 80\% of time steps are reserved for training and the remaining 20\% for testing. This prevents \textbf{data leakage}, which would occur with a random split because overlapping windows (stride 32 over a 512-point window) share up to 94\% of their data points.
    \item \textbf{Sliding Window Extraction:} Each split is independently sliced into overlapping windows (size 512, stride 32).
    \item \textbf{Threshold-Based Labeling:} A window is only labeled as a specific anomaly class if the anomaly occupies at least \textbf{10\%} of the window length. This prevents the CNN from learning that windows containing 99\% pure noise should be classified as anomalies. When the threshold is met, the most frequent anomaly class ID within the window is assigned via majority voting.
    \item \textbf{Per-Window Centering (Instance Normalization):} To make the network robust against the slowly wandering background baseline generated by the Ornstein-Uhlenbeck process, each sliding window is independently centered by subtracting its own local mean $\mu_{\mathrm{window}}$. However, a global standard deviation $\sigma_{\mathrm{train}}$ is computed across all centered training windows to preserve the relative amplitudes of the spikes. The test set is scaled using this same global statistic. This value is persisted to \texttt{normalization\_stats.json} for identical inference normalization:
    \begin{equation}
        x_{\mathrm{scaled}} = \frac{x - \mu_{\mathrm{window}}}{\sigma_{\mathrm{train}}}
    \end{equation}
    \item \textbf{Tensor Reshaping:} The output is reshaped into the strict \texttt{(Batch\_Size, 1, Window\_Size)} format required by PyTorch's \texttt{Conv1d} layers.
\end{enumerate}

\subsection{Architecture Definition (\texttt{model.py})}
The \texttt{Anomaly1DCNN} class inherits from \texttt{torch.nn.Module} and implements a 3-block convolutional architecture with a progressively narrowing kernel strategy:
\begin{itemize}
    \item \textbf{Block 1:} \texttt{Conv1d(in=1, out=16, kernel=7, padding=3)} $\rightarrow$ \texttt{BatchNorm1d} $\rightarrow$ \texttt{ReLU} $\rightarrow$ \texttt{MaxPool1d(2)}.
    \item \textbf{Block 2:} \texttt{Conv1d(in=16, out=32, kernel=7, padding=3)} $\rightarrow$ \texttt{BatchNorm1d} $\rightarrow$ \texttt{ReLU} $\rightarrow$ \texttt{MaxPool1d(2)}.
    \item \textbf{Block 3:} \texttt{Conv1d(in=32, out=64, kernel=5, padding=2)} $\rightarrow$ \texttt{BatchNorm1d} $\rightarrow$ \texttt{ReLU} $\rightarrow$ \texttt{MaxPool1d(2)}.
\end{itemize}
The early layers use larger kernels (7) to capture broad temporal structure such as the overall envelope of anomaly shapes, while the final layer uses a smaller kernel (5) to refine local features. The channel count doubles at each block (16 $\rightarrow$ 32 $\rightarrow$ 64), progressively expanding the network's feature representation capacity.

The network utilizes a \textbf{Regional Pooling layer} (\texttt{AdaptiveAvgPool1d(4)}) instead of Global Average Pooling. This preserves 4 distinct temporal bins, allowing the network to recognize the temporal topography of shapes---for example, distinguishing the two separate peaks of an \texttt{M} shape from a solid \texttt{bell\_sq} block, since the averaged values in each bin differ between these shapes.

This flattened vector of size 256 ($64 \times 4$) is then passed through a classifier head: \texttt{Flatten()} $\rightarrow$ \texttt{Dropout(0.4)} $\rightarrow$ \texttt{Linear(256, 32)} $\rightarrow$ \texttt{ReLU} $\rightarrow$ \texttt{Dropout(0.2)} $\rightarrow$ \texttt{Linear(32, 7)}. The total model footprint is \textbf{22,727 trainable parameters}.

\subsection{Training Loop (\texttt{train.py})}
The training script establishes the complete PyTorch training ecosystem with GPU acceleration and comprehensive logging:
\begin{itemize}
    \item \textbf{Data Split:} The training set is further divided 80/20 into train/validation subsets using a random permutation for early stopping monitoring.
    \item \textbf{Class Imbalance Handling:} Computes inverse frequency weights $w_c = \frac{N_{\mathrm{total}}}{C \cdot N_c}$ and passes them to the \texttt{CrossEntropyLoss} criterion, forcing the optimizer to treat rare anomaly shapes with the same importance as the dominant normal background.
    \item \textbf{Optimization:} Adam optimizer with initial learning rate $10^{-3}$.
    \item \textbf{Learning Rate Scheduling:} \texttt{ReduceLROnPlateau} (patience 2, factor 0.5) monitors validation loss and halves the learning rate when progress stalls.
    \item \textbf{Early Stopping:} Patience of 5 epochs. The best model weights are saved only when validation loss improves.
    \item \textbf{Logging:} A comprehensive \texttt{.txt} log and an interactive Plotly training curves chart (HTML + PNG) are generated.
\end{itemize}

\subsubsection{Training Results}
The model was trained on a 10M-point synthetic dataset (249,985 windows) on an NVIDIA GeForce RTX 5060 Laptop GPU with CUDA 12.8:
\begin{itemize}
    \item \textbf{Convergence:} 82 epochs, 9 minutes 5 seconds. Learning rate decayed from $10^{-3}$ to $8 \times 10^{-6}$ across 7 reduction steps.
    \item \textbf{Final losses:} Best validation loss = 0.2494, test loss = 0.3028.
    \item \textbf{Test accuracy:} 93.4\% per-window accuracy (62,485 windows). Event-level accuracy is significantly higher due to overlapping window accumulation during inference.
\end{itemize}

\subsection{Architecture Search}
The final architecture was selected through an empirical search over several candidate configurations. All variants were trained on the same 10M-point dataset and evaluated on both per-window test accuracy and event-level inference over a 100,000-point segment containing 77 anomaly events:

\begin{itemize}
    \item \textbf{Depth vs.\ Width:} Reducing the number of convolutional blocks below 3 degrades performance unless channel width is increased. A 2-block model with narrow channels (16$\rightarrow$32) lacked sufficient representational capacity, while a 2-block model with wider channels (32$\rightarrow$64) recovered most accuracy.
    \item \textbf{Diminishing returns of depth:} Blocks 4 and 5 contributed negligible accuracy gains while inflating the parameter count by $12\times$.
    \item \textbf{Training speed:} Tightening early stopping patience from 10 to 5 and LR scheduler patience from 4 to 2, combined with doubling the batch size to 128, reduced training time without affecting convergence.
\end{itemize}

\subsection{Inference and Evaluation (\texttt{visualize\_inference.py})}
The inference script evaluates the trained model on a continuous segment of the dataset using a fine-grained sliding window (stride 10, window 512). Two key design decisions:

\begin{enumerate}
    \item \textbf{Consistent Normalization:} The inference script loads the global $\sigma_{\mathrm{train}}$ from \texttt{normalization\_stats.json} and applies the same per-window centering strategy.
    \item \textbf{Overlapping Window Accumulation:} The softmax probability vector is \textbf{accumulated} across all points covered by each window. With stride 10 and window 512, each point is covered by up to 51 overlapping windows. The final per-point class probability is the average:
    \begin{equation}
        P_{\mathrm{final}}(c \mid t) = \frac{1}{|\mathcal{W}_t|} \sum_{w \in \mathcal{W}_t} P_w(c)
    \end{equation}
    where $\mathcal{W}_t$ is the set of all windows covering time step $t$. This ensemble-like averaging significantly reduces prediction noise.
\end{enumerate}

\subsection{Robustness Analysis (\texttt{robustness\_test.py})}
To assess the model's sensitivity to degraded signal conditions, a robustness test independently sweeps two axes while holding the other at its training baseline:
\begin{enumerate}
    \item \textbf{Background noise intensity:} The standard deviation of the high-frequency sensor noise was scaled from $1\times$ to $3\times$ the baseline value ($\sigma = 2.70$ gamma dose units).
    \item \textbf{Anomaly shape deformation:} The variance parameter of the anomaly generator was scaled from $1\times$ to $8\times$ the baseline value (0.04), controlling how much each anomaly instance deviates from its canonical template shape.
\end{enumerate}

Each configuration generated a test dataset with 50 anomaly events using a fixed random seed to ensure identical anomaly positions and template selections across all runs.
